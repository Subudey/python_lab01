# toolkit — консольный калькулятор и конвертер величин

Python-пакет с CLI, объединяющий калькулятор арифметических выражений (без `eval`/`exec`) и конвертер единиц измерения длины, массы и температуры.

## Установка

```bash
pip install -e .
```

## Использование

```bash
python -m toolkit calc "2 + 3 * 4"               # 14.0
python -m toolkit convert 100 --from cm --to m   # 1.0
python -m toolkit --help
```

Калькулятор поддерживает целые и вещественные числа, операции `+ - * /` и унарные `+`/`-` перед числом, соблюдая приоритет `*`/`/` над `+`/`-`.

Конвертер работает с тремя группами единиц: длина (`mm cm m km`), масса (`g kg`), температура (`c f k`). Регистр единиц не важен. Конвертация между разными группами и температура ниже абсолютного нуля — ошибки.

При некорректном вводе CLI печатает сообщение в stderr и завершается с кодом `2`, при успехе — с кодом `0`.

## Алгоритм калькулятора

Вычисление выражения устроено как конвейер из четырёх независимых шагов, каждый из которых реализован отдельной функцией в `calculator.py`.

**1. Токенизация (`tokenize`).** Строка выражения разбирается слева направо: операторы `+ - * /` и пробелы распознаются посимвольно, а числа (целые и вещественные) — с помощью скомпилированного регулярного выражения из `constants.py`, которое захватывает подряд идущие цифры и не более одной точки. Если очередной символ не подходит ни под один из этих случаев — сразу кидается `InvalidCharacterError`. На этом шаге функция ничего не знает о смысле последовательности токенов, она только размечает текст.

**2. Валидация (`validate`).** Готовый список токенов проверяется на структурную корректность: список не пуст, не начинается и не заканчивается недопустимым оператором, не содержит двух чисел подряд без оператора между ними и не содержит двух бинарных операторов подряд. Единственное разрешённое исключение из последнего правила — унарный `+`/`-` сразу после другого оператора, если следом идёт число (например, `5 * -3`). При нарушении любого из правил кидается соответствующая ошибка (`EmptyExpressionError`, `MissingNumError`, `MissingOperatorError`, `TwoBinaryOperatorsError`).

**3. Разрешение унарности (`resolve_unary`).** Список токенов проходится ещё раз, и каждая пара «унарный знак + число» схлопывается в один токен-число с уже применённым знаком (например, `-` и `3` превращаются в `-3.0`). После этого шага в списке строго чередуются числа и бинарные операторы, что упрощает финальное вычисление.

**4. Вычисление (`calculate`).** Значение сворачивается в два прохода, чтобы соблюсти приоритет операций. Сначала слева направо схлопываются все `*` и `/` — каждая пара «число, оператор, число» заменяется результатом, при делении на ноль кидается `DivisionByZeroError`. На втором проходе оставшиеся `+`/`-` (все с одинаковым приоритетом) сворачиваются в одно итоговое число.

`__main__.py` вызывает эти шаги по очереди (`tokenize → validate → calculate`) и оборачивает их в `try/except`, чтобы превратить любую ошибку пакета в понятное сообщение в stderr и код возврата `2`.

## Алгоритм конвертера

Для длины и массы конвертация линейна: у каждой единицы в `constants.py` есть коэффициент — во сколько раз она больше базовой единицы группы (метра для длины, грамма для массы). Перевод выполняется в два действия: исходное значение сначала переводится в базовую единицу (умножением на коэффициент), затем из базовой — в целевую (делением на коэффициент целевой единицы).

Для температуры коэффициенты не подходят, потому что шкалы Цельсия и Фаренгейта не совпадают в нуле, поэтому используются явные формулы пересчёта через Кельвины как общую точку отсчёта. Полученное значение в Кельвинах проверяется на отрицательность — если оно меньше нуля, конвертация невозможна физически, и кидается `BelowAbsoluteZeroError`.

Перед всеми вычислениями `get_group` определяет, к какой из трёх групп относится каждая единица (приводя её к нижнему регистру), и если `unit_from` и `unit_to` оказываются в разных группах, конвертация отклоняется как `IncompatibleUnitsError`.

Сами таблицы единиц не зашиты в коде, а загружаются при импорте `constants.py` из конфигурационного файла `src/resources/units_config.json` — JSON-объект с ключами `length`, `mass` (коэффициенты) и `temperature` (список допустимых единиц). Чтобы изменить набор поддерживаемых единиц или коэффициенты пересчёта, достаточно отредактировать этот файл, не трогая код.

## История вычислений

Каждый успешный вызов `calc` дописывает запись `{"expression": ..., "result": ...}` в файл `src/resources/history.json` (модуль `history_writer.py`). Файл при необходимости создаётся автоматически; при ошибке вычисления запись не делается — в историю попадают только успешные выражения.

## Примеры

```bash
python -m toolkit calc "2 + 3 * 4"
# 14.0

python -m toolkit calc "-5 / 2"
# -2.5

python -m toolkit calc "5 / 0"
# Деление на ноль                          (stderr, код возврата 2)

python -m toolkit convert 100 --from cm --to m
# 1.0

python -m toolkit convert 20 --from c --to f
# 68.0

python -m toolkit convert 5 --from km --to kg
# Несовместимые единицы измерения          (stderr, код возврата 2)
```
